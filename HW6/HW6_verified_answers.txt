Reference indexing - What does it mean to index a FASTA file?

Command:
  samtools faidx S288C_reference_sequence_R64-2-1_20150113.fasta

Answer:
  Indexing a FASTA file creates a .fai file containing each reference
  sequence's name, length, byte offset, number of bases per line, and
  number of bytes per line. This permits rapid access to particular genomic
  regions without scanning the whole FASTA file.

Variant-calling commands (as used for the assignment):

PART III - VARIANT CALLING WITH GATK
------------------------------------

BAM preparation (read groups):
  gatk AddOrReplaceReadGroups \
    -I SRR1569760_vs_S288C.HQ.sort.bam \
    -O SRR1569760_vs_S288C.HQ.sort.RG.bam \
    -LB READS -PL ILLUMINA -PU 1 -SM SRR1569760 \
    --CREATE_INDEX true

What is the purpose of the reference sequence dictionary (.dict)?

  A sequence dictionary records metadata for the reference contigs,
  including their names, lengths, order and (usually) MD5 checksums.
  GATK uses this information to validate reference compatibility
  with the BAM and interval definitions.

Dictionary creation:
  gatk CreateSequenceDictionary \
    -R S288C_reference_sequence_R64-2-1_20150113.fasta \
    -O S288C_reference_sequence_R64-2-1_20150113.dict

Calling variants on ChrII:
  gatk HaplotypeCaller \
    -R S288C_reference_sequence_R64-2-1_20150113.fasta \
    -I SRR1569760_vs_S288C.HQ.sort.RG.bam \
    -O ChrII.gatk.vcf -L ChrII

Q8. Are the bcftools and GATK results similar? Which is correct?

  Yes, the results are very similar. After quality filtering:
    bcftools: 4,093 records
    GATK:     4,131 records

  After left-alignment and splitting multiallelic records, the
  normalized comparison yielded:
    Shared by both callers: 4,036 records
    Only bcftools:            69 records
    Only GATK:              102 records

  These values were independently reproduced by bcftools isec.
  Note that normalization with '-m -any' can increase record counts by
  splitting a multiallelic record into multiple records. Thus the
  normalized totals (4,105 for bcftools and 4,138 for GATK) differ from
  the original filtered VCF line counts (4,093 and 4,131).
  About 98.3% of normalized bcftools records and 97.5% of normalized
  GATK records are shared.

  Differences may occur because bcftools uses pileup-based variant
  calling, whereas GATK HaplotypeCaller performs local haplotype
  assembly. Indels and repetitive regions are particularly sensitive
  to differences in representation and calling strategy.

  Neither caller can be declared correct from these data alone.
  Resolving discordant calls would require independent validation,
  such as a trusted RM11 assembly, long-read data or targeted sequencing.
  IGV inspection can help assess read support but is not a definitive
  truth set.

  Optional note: The original report mentions heterozygous calls in
  a nominally homozygous strain. These could reflect mapping errors,
  sample biology or other artifacts; heterozygous calls should not
  automatically be classified as errors without validation.

  Comparison commands:
